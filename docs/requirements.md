## Ambiguities and adopted interpretations

1. The screenshot allows creating or obtaining a CSV and gives no source. UCI Online Retail was selected because it offers public real transaction records and an explicit reuse license.
2. The source is an online retailer with Country and StockCode, while the scenario mentions physical stores and product categories. Country is explicitly used as a sales-market proxy for Store Location. The first two StockCode characters define a deterministic category grouping. These values preserve provenance and are described as proxies.
3. The source has GBP prices while the filter is written in INR. Acquisition applies a configurable documented multiplier, preserves original GBP values, and uses 100 as an illustrative default. It has no historical FX claim.
4. One invoice contains several product lines. Transaction ID is a unique line key formed from original InvoiceNo and Excel row number, so the required transaction calculation is a line-total calculation.
5. Best-selling is unspecified. This implementation ranks by total positive units, then product name to resolve ties.
6. Profitability appears in the scenario but no cost attribute or profit calculation is listed. The implementation generates revenue/quantity rankings and states that net profit requires cost data.
7. Returns, cancellations, zero prices, duplicates, and missing attributes require a policy. They remain visible in the audit and are excluded from positive-sales calculations. Revenue is gross positive sales for the retained subset.
8. The original workbook exceeds the form's dataset upload size. The packaged prepared CSV is the adapted first-500-row public mirror subset, accompanied by an exact selection rule and source checksum manifest. The default official acquisition produces a first-10,000-row subset. The original source link remains separate.
9. A local run demonstrates partitions, tasks, shuffles, and Spark plans on local workers. A real cluster run requires accessible shared data and compatible executors. The methodology explains cluster distribution, and no cluster benchmark is claimed without execution.
10. Spark UI and DAG screenshots require capture from a real run. Event logs and query plans are generated automatically. The screenshot procedure is included, and any supplied captured screenshots must be described in `docs/validation.md`.
